# Security policy

Security reports are appreciated and should be handled privately.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion, pull request, or social post.

Use the affected repository's **Report a vulnerability** option when private vulnerability reporting is available. If it is not available, contact Jeremy through [devdudejeremy.com](https://devdudejeremy.com) and include:

- the affected repository, page, or component;
- a concise description of the issue and its likely impact;
- reproducible steps or a minimal proof of concept;
- any relevant environment or version details; and
- whether the issue has been shared with anyone else.

Do not access data that is not yours, disrupt a live service, use destructive testing, or retain sensitive information while investigating.

## Response and disclosure

Reports will be acknowledged as soon as practical. Validation, remediation, and disclosure timing depend on the severity and complexity of the issue. Please allow a reasonable opportunity to investigate and correct the problem before publishing details.

This policy does not create a bug-bounty program or promise compensation.
