# Support

## Questions about an open-source project

Start with that repository's README, setup instructions, and existing issues. If you find a reproducible defect or have a focused feature proposal, open an issue in the repository where the behavior lives.

Include the smallest useful example, what you expected, what happened, and relevant version or environment details. Please do not include secrets, private data, or production credentials.

## Security concerns

Do not open a public support issue for a suspected vulnerability. Follow the private reporting process in [SECURITY.md](SECURITY.md).

## Project and consulting inquiries

For custom web applications, RAG and AI assistants, Codex or Claude workflow systems, and ongoing software maintenance, visit [devdudejeremy.com](https://devdudejeremy.com).

Open-source repositories are provided without a guaranteed response time or service-level agreement. Commercial support and maintenance arrangements can be discussed separately.
