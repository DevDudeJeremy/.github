# Contributing

Thank you for taking the time to improve a DevDudeJeremy project.

The repositories in this organization are independent projects. Before contributing, read the target repository's README and local contribution guidance; its setup, testing, and release instructions take precedence over this organization-wide guide.

## Before opening a change

- Search existing issues and pull requests to avoid duplicate work.
- Open an issue before beginning a substantial feature, dependency migration, or architectural change.
- Keep changes focused. Unrelated cleanup is easier to review as a separate pull request.
- Never include credentials, private data, production configuration, or third-party content you do not have permission to share.
- Report suspected vulnerabilities privately according to [SECURITY.md](SECURITY.md), not in a public issue.

## Pull requests

A useful pull request explains:

1. What problem it solves.
2. Why the chosen approach fits the project.
3. How the change was tested.
4. Any migration, deployment, accessibility, security, or compatibility considerations.

Please update documentation and tests when behavior changes. Screenshots or short recordings are welcome for visible interface work.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
